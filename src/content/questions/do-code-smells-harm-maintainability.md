---
title: Do design flaws make code harder to maintain?
summary: Code smells and antipatterns are widely treated as signs of poor design. Does code that contains them actually change more often, break more often, or take more effort to maintain?
area: evolution
---

## Why it matters

Refactoring to remove smells costs effort that could go to features or fixes. If smells cause maintenance problems, removing them is an investment; if their apparent effect is explained by other factors such as size, refactoring them yields little.

## Scope

Includes the relationship between code smells or antipatterns and change-proneness, fault-proneness, and maintenance effort. Excludes the accuracy of smell detection tools.
